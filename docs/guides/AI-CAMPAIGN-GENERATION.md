## 1. The Core Process

The AI campaign generation process uses a **generate → validate → fix → repeat** loop:

```
 ┌─────────────────────────────────────────────────────┐
 │                     START                           │
 │  Feed prompt kit + theme idea to AI                │
 └─────────────────────┬───────────────────────────────┘
                       ↓
 ┌─────────────────────────────────────────────────────┐
 │  PHASE 1: AI GENERATES JSON FILES                   │
 │  - Uses schema contract + cross-ref map             │
 │  - Generates files in dependency order (Phase 0-3)  │
 │  - Outputs to a campaign directory                  │
 └─────────────────────┬───────────────────────────────┘
                       ↓
 ┌─────────────────────────────────────────────────────┐
 │  PHASE 2: VALIDATE                                  │
 │  bun scripts/run-validator.ts --campaign-dir ./camp │
 │  - Zod schema validation (structural correctness)   │
 │  - Deep cross-reference validation (7 validators)   │
 │  - Outputs errors to console or --json              │
 └─────────────────────┬───────────────────────────────┘
                       ↓
          ┌────────────┴────────────┐
          ↓                        ↓
    ┌──────────┐            ┌──────────────┐
    │ CLEAN ✅ │            │ ERRORS ❌    │
    │ No       │            │ Feed errors  │
    │ errors   │            │ back to AI   │
    │          │            │ for fixing   │
    └────┬─────┘            └──────┬───────┘
         ↓                        ↓
    ┌──────────────────────────────────────┐
    │  PHASE 3: HUMAN REVIEW               │
    │  - Narrative coherence               │
    │  - Balance / difficulty tuning       │
    │  - Optional: AI Arena simulations    │
    │  - Manual playtest                   │
    └──────────────────────────────────────┘
```

## 2. Tooling Overview

### 2.1 Prompt Kit Generator
**Script:** [`scripts/generate-ai-prompt-kit.ts`](scripts/generate-ai-prompt-kit.ts)

Auto-extracts all Zod schemas, cross-reference maps, and valid values into a structured prompt kit that an AI can consume.

```bash
bun scripts/generate-ai-prompt-kit.ts
# Creates ./ai-prompt-kit/ with:
#   schema-contract.md       — All Zod schemas
#   cross-reference-map.md   — Field-by-field cross-ref table
#   valid-values.json        — All enum/literal values
#   generation-rules.md      — Ordering and constraints
#   default-campaign/        — Reference implementation
#   README.md                — Kit overview
```

Run this **after any schema changes** to regenerate the kit.

### 2.2 Campaign Validator
**Script:** [`scripts/run-validator.ts`](scripts/run-validator.ts)

Validates campaign data against Zod schemas and 7 cross-reference validators.

```bash
# Validate the built-in default campaign
bun scripts/run-validator.ts

# Validate a custom campaign directory
bun scripts/run-validator.ts --campaign-dir ./my-campaign

# Machine-parseable JSON output (for AI feedback loop)
bun scripts/run-validator.ts --campaign-dir ./my-campaign --json
```

**Exit codes:**
- `0` — Validation passed (0 errors)
- `1` — Validation failed (errors found)
- `2` — Fatal error (crash)

### 2.3 Campaign Bootstrap Generator
**Script:** [`scripts/bootstrap-campaign.ts`](scripts/bootstrap-campaign.ts)

Generates a minimal, structurally-valid campaign skeleton dynamically reading from `CampaignDataSchema`. Passes all validators cleanly.

```bash
bun scripts/bootstrap-campaign.ts --out-dir ./my-campaign
bun scripts/bootstrap-campaign.ts --out-dir ./my-campaign --name "My Campaign" --id "my-campaign"
```

### 2.4 Tooling Linter
**Command:** `bun run lint:scripts`

Validates the TypeScript code for the generator scripts themselves against a dedicated strict configuration. Run this if you modify any scripts to ensure they remain error-free.

## 3. The Prompt Kit

The `ai-prompt-kit/` directory (generated by `scripts/generate-ai-prompt-kit.ts`) contains everything an AI needs:

| File | What It Contains | How to Use |
|------|-----------------|------------|
| [`schema-contract.md`](ai-prompt-kit/schema-contract.md) | All Zod schemas as documented TypeScript interfaces — every field, type, and constraint. | The AI reads this to understand what fields exist, what types they are, and what values are valid. |
| [`cross-reference-map.md`](ai-prompt-kit/cross-reference-map.md) | Field-by-field table showing which files reference which registries. | The AI reads this to avoid hallucinating IDs. Every arrow is a potential failure point. |
| [`valid-values.json`](ai-prompt-kit/valid-values.json) | Every enum value, literal union member, and valid string constant. | The AI reads this to know exactly what values are legal for each enum/union field. |
| [`generation-rules.md`](ai-prompt-kit/generation-rules.md) | Generation ordering, constraints, and common pitfalls. | The AI reads this to understand the "gotchas" before generating. |
| [`default-campaign/`](ai-prompt-kit/default-campaign/) | The complete default campaign as an annotated reference implementation. | The AI studies this to understand how real campaigns implement each concept. |

### How to Feed the Kit to an AI

Include the entire prompt kit in your AI prompt. A good structure:

1. **Role assignment**: "You are generating a campaign for a TypeScript roguelike..."
2. **Include all files from `ai-prompt-kit/`**
3. **Specify theme**: "Generate a campaign with theme: [your idea]"
4. **Specify output**: "Create all 32 JSON files in `./my-campaign/`"
5. **Constraint**: "After generating, I will validate with `run-validator.ts` and feed errors back for fixing."

## 4. The Iterative Fix Loop

When the validator returns errors, format them for the AI:

**Step 1:** Run validator with `--json` flag
```bash
bun scripts/run-validator.ts --campaign-dir ./my-campaign --json
```

**Step 2:** The output is machine-parseable:
```json
{
  "valid": false,
  "campaignId": "my-campaign",
  "errorCount": 5,
  "warnings": [...],
  "errors": [
    {
      "severity": "error",
      "path": "/items/fire_sword/consumable/effectId",
      "message": "Item references effectId 'burning_slash' which does not exist in effects.json"
    },
    {
      "severity": "error",
      "path": "spawnPools.forest_monsters.entities",
      "message": "Spawn pool references entity 'wolf' which does not exist in entities.json"
    }
  ]
}
```

**Step 3:** Feed the errors back to the AI:
```
VALIDATION FAILED with 5 errors:

[Error 1] ERROR @ items/fire_sword/consumable/effectId:
  Item references effectId "burning_slash" which does not exist in effects.json

[Error 2] ERROR @ spawnPools.forest_monsters.entities:
  Spawn pool references entity "wolf" which does not exist in entities.json

Please fix ALL errors and regenerate the affected files.
```

**Step 4:** Repeat until the validator reports `"valid": true`.

## 5. Generation Ordering (Dependency Phases)

Campaign files must be generated in dependency order because later files reference IDs from earlier files.

### Phase 0: Foundation (No Dependencies)
Generate these first. They depend on nothing.

| File | Description |
|------|-------------|
| `manifest.json` | Campaign metadata (ID, name, version) |
| `theme.json` | Color palette, glyphs, UI config |
| `advancement.json` | XP-to-level table |
| `tiles.json` | Tile type definitions (wall, floor, water, etc.) |
| `factions.json` | 2D faction hostility matrix |
| `status.json` | Status effect definitions (poison, haste, etc.) |
| `tag_registry.json` | Central registry of ALL tags used in the campaign |
| `fields.json` | Field type definitions (fire, smoke, etc.) |
| `trait_registry.json` | Dynamic trait definitions (elite, regenerating) |
| `encounter_profiles.json` | Budget allocation profiles (protein/appetizer/side/dessert) |
| `rules.json` | Game rules (map size, hunger, spawn weights) — references tile/area IDs |

### Phase 1: Entity Definitions (Depend on Phase 0)
These reference Phase 0 IDs.

| File | Dependencies |
|------|-------------|
| `effects.json` | `status.json` (statusId) |
| `ai.json` | — (stands alone) |
| `entities.json` | `factions.json` (faction), `ai.json` (profileId), `tag_registry.json` (tags), `trait_registry.json` (traits), `dialogues.json` (dialogueId), `triggers.json` (trap.triggerId) |

### Phase 2: Content (Depend on Phase 0+1)

| File | Dependencies |
|------|-------------|
| `items.json` | `effects.json` (effectId), `status.json` (onHit.statusId), `tag_registry.json` (tags) |
| `areas.json` | `tiles.json` (tile IDs), `entities.json` (entity IDs), `encounter_profiles.json` (profileId), `tag_registry.json` (tags/sub-biomes) |
| `schemes.json` | `villains.json` (villainArchetypeId) |
| `villains.json` | `factions.json` (faction standing) |
| `agreements.json` | `tag_registry.json` (clue templates) |
| `spawn_pools.json` | `entities.json` (entity keys), `tag_registry.json` (tags), `factions.json` (faction tags) |

### Phase 3: Interactions (Depend on Everything Above)

| File | Dependencies |
|------|-------------|
| `dialogues.json` | Everything (conditions/consequences reference entities, items, quests, factions, areas) |
| `quests.json` | `entities.json` (kill/talk targets), `items.json` (gather targets), `areas.json` (explore targets), `factions.json` (standing rewards) |
| `triggers.json` | Everything (conditions/consequences reference entities, areas, quests, effects) |
| `reactions.json` | Everything (tags, traits, entities, items, tiles, fields) |

### Phase 4: Social & Nemesis (Depend on Everything Above)

| File | Dependencies |
|------|-------------|
| `identity_generation.json` | — (stands alone) |
| `personality_generation.json` | — (stands alone) |
| `nemesis_hierarchies.json` | `factions.json` (faction bindings) |
| `knowledge_propagation.json` | `factions.json`, `tag_registry.json` |
| `rumor_propagation.json` | `factions.json`, `tag_registry.json` |
| `relationship_thresholds.json` | `triggers.json` (consequences) |

## 6. Critical Constraints

### 6.1 Faction Matrix Must Be Complete
Every faction ID must appear as both a row AND column key. If `"goblins"` exists as a row, it must also exist as a column. The matrix is NOT automatically symmetric.

```json
{
  "player": { "player": "friendly", "monster": "hostile" },
  "monster": { "player": "hostile", "monster": "neutral" }
  // ✅ Both "player" and "monster" are row keys AND column keys
}
```

### 6.2 Encounter Profile Budget Must Sum to 1.0
```json
{
  "budgetAllocation": {
    "protein": 0.6,
    "appetizer": 0.1,
    "side": 0.2,
    "dessert": 0.1   // Sum: 1.0 ✅
  }
}
```

### 6.3 Areas Must Form a Connected Graph
Every area must be reachable from the starting area (defined in `rules.json` → `map.startingAreaId`). If area A has a connection to area B, area B must exist and must have a reciprocal connection OR the connection must be directional as intended (e.g., `"direction": "edge"` portals).

### 6.4 Every Tag Must Be Registered
Any tag used in entities, items, reactions, spawn pools, areas, or any other file **must** have an entry in `tag_registry.json`. This is enforced by the tag validator.

### 6.5 Dialogue Tree Internal Consistency
Every `nextNodeId` in a dialogue option must point to a node that exists in the same dialogue tree's `nodes` map.

### 6.6 Quest Objective targetId Must Match Objective Type
- `"kill"` → targetId must be an entity template ID from `entities.json`
- `"gather"` → targetId must be an item ID from `items.json`
- `"explore"` → targetId must be an area ID from `areas.json`
- `"talk"` → targetId must be an entity template ID from `entities.json`

## 7. Common Pitfalls & How to Avoid Them

| Pitfall | Example | How to Avoid |
|---------|---------|-------------|
| **Unregistered tag** | `"undead"` used in reactions but not in `tag_registry.json` | Before using a new tag, add it to `tag_registry.json` |
| **Missing faction entry** | Entity has `faction: "goblin_tribe"` but no such faction in `factions.json` | Check every `faction` field against `factions.json` keys |
| **Broken area connection** | Area `"dungeon_5"` connects to `"dungeon_6"` which doesn't exist | Verify `targetAreaId` against existing area IDs |
| **Invalid trigger eventType** | Trigger uses `eventType: "FullMoon"` — not a valid `GameEventType` | Use only the 19 values from `GameEventType` enum |
| **Encounter profile budget error** | `budgetAllocation` sums to 1.2 instead of 1.0 | Always verify: `protein + appetizer + side + dessert === 1.0` |
| **Quest target mismatch** | Quest objective type `"kill"` references entity `"dragon"` but no such entity | Match objective type to the correct registry |
| **Spawn pool entity doesn't exist** | Spawn pool lists `entities: { "wolf": 100 }` but no `"wolf"` in `entities.json` | Check every spawn pool entity key against `entities.json` |
| **Effect ID doesn't exist** | Item `consumable.effectId: "fireball"` but no `"fireball"` in `effects.json` | Verify effect IDs against `effects.json` |
| **Status effect ID doesn't exist** | Effect `apply_status.statusId: "paralyze"` but no `"paralyze"` in `status.json` | Verify status IDs against `status.json` |
| **Reaction verb mismatch** | Reaction uses verb `"zap"` but the reaction system may not handle that context | Stick to the canonical verb list |
| **Missing tile ID in static map** | Static map legend references `"#" : "stone_wall"` but no `"stone_wall"` in `tiles.json` | Every legend value must be a key in `tiles.json` |

```
You are a campaign generator for a TypeScript roguelike engine.
The engine validates all data through Zod schemas and a multi-pass validator.

Your task: Generate a complete campaign with 32 JSON files.

=== REFERENCE MATERIALS ===

[SCHEMA CONTRACT]
[Insert the entire ai-prompt-kit/schema-contract.md content]

[CROSS-REFERENCE MAP]
[Insert the entire ai-prompt-kit/cross-reference-map.md content]

[VALID VALUES]
[Insert the entire ai-prompt-kit/valid-values.json content]

[GENERATION RULES]
[Insert the entire ai-prompt-kit/generation-rules.md content]

[DEFAULT CAMPAIGN]
[Reference: ai-prompt-kit/default-campaign/ directory]

=== CAMPAIGN SPECIFICATION ===

Theme: [DESCRIBE YOUR THEME HERE]
Campaign ID: [e.g., "forest-temple"]
Campaign Name: [e.g., "The Forest Temple"]
Author: [Your name]
Required features: [e.g., "at least 3 areas, 5 monster types, 2 quests"]

=== GENERATION RULES ===

1. Generate files in Phase 0 → 1 → 2 → 3 order.
2. Every cross-reference must resolve to an existing ID.
3. Every tag must be registered in tag_registry.json.
4. Faction matrix must be complete (symmetric entries).
5. Encounter profile budgets must sum to 1.0.
6. Areas must form a connected graph.
7. Output all 32 files to the ./[campaign-id]/ directory.

=== OUTPUT FORMAT ===

For each file, output:
```json
// [filename]
<JSON content>
```

Begin with Phase 0 files.
```

## 9. Validator Error Reference

### Zod Schema Errors
These occur when the JSON structure doesn't match the schema contract.

| Error | Common Cause |
|-------|-------------|
| `Expected string, received number` | Wrong type for a field |
| `Expected enum, received "invalid"` | Value not in the allowed enum set |
| `Required` | Missing required field |
| `Expected array, received object` | Wrong structure |
| `Unrecognized key(s)` | Extra field not in schema |

### Cross-Reference Validator Errors

| Validator | Error Pattern | Meaning |
|-----------|---------------|---------|
| **Tags** | `references unregistered tag` | Tag used but not in `tag_registry.json` |
| **Items** | `effectId "X" does not exist` | Item references missing effect |
| **Items** | `statusId "X" does not exist` | Item onHit references missing status effect |
| **Reactions** | `references unknown tag` | Reaction matcher uses unregistered tag |
| **Reactions** | `ambiguous reactions` | Two reactions have identical matchers and priority |
| **Quests** | `objective targetId not found` | Quest objective references non-existent entity/item/area |
| **Triggers** | `eventType not valid` | Trigger uses non-existent event type |
| **Encounters** | `overspent budget` | Area has CR budget but all candidates cost more |
| **Encounters** | `dead spawn pool` | Pool conditions match no area in campaign |
| **Encounters** | `budget scaling sanity` | Negative baseBudget or scalingFactor |
| **Reachability** | `unreachable area` | Area not connected to the graph |

## Quick Start Workflow

```bash
# 1. Generate the prompt kit (run once, or after schema changes)
bun scripts/generate-ai-prompt-kit.ts

# 2. Create a bootstrap skeleton
bun scripts/bootstrap-campaign.ts --out-dir ./my-campaign --name "My Campaign"

# 3. Feed the ai-prompt-kit/ + your theme to an AI
#    The AI generates content for each JSON file.

# 4. Validate after each round of generation
bun scripts/run-validator.ts --campaign-dir ./my-campaign --json

# 5. Feed errors back to AI, fix, repeat until clean.

# 6. Manually review narrative coherence and balance.
```
